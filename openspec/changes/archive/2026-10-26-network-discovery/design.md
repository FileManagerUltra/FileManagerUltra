## Decisions
1. **Virtual scheme.** `network:///` (`Scheme::Network`, empty authority, path `/`) served by `NetworkFs`, a read-only `Vfs` over a shared host list. Children are Dir entries whose URIs are `smb://host[:port]/` or `sftp://host[:port]/`. Everything else on it returns `Unsupported`.
2. **Discovery is passive state.** A background thread owns the mDNS daemon and a WS-Discovery socket and updates an `Arc<Mutex<Vec<Host>>>` (cap 512, deduplicated by service and address). The UI and `read_dir` only read a snapshot; nothing blocks. Started on first read of `network:///`, stopped with the session.
3. **mDNS** via the pure-Rust `mdns-sd` crate: browse `_smb._tcp.local.` and `_sftp-ssh._tcp.local.`. **WS-Discovery**: multicast `Probe` (UDP 239.255.255.250:3702) every 30 s, parse `XAddrs` for the address; hosts already known by mDNS (same IP) are skipped. NetBIOS broadcast is out of scope.
4. **Untrusted input.** Names from the network are length-capped, control characters stripped, and shown as unverified; they never form a path without `VfsUri::join` validation.
5. **Login prompt, not form.** Reading an `smb://` URI with no backend registers a pending `LoginPrompt {host, port, user, domain}` instead of an error. The dialog dispatches `remote.connect.smb` with an empty share, which signs in only; the root then lists shares. Cancel clears the prompt and leaves the tree unchanged. A wrong password re-opens the prompt with the error.
6. **Credential cache.** "Remember until quit" keeps `(user, domain, password)` per host in memory (`SecretString`, never `Debug`, wiped on exit). "Forget immediately" keeps the login only inside the live connection for reconnects, as today. No on-disk option.
7. **SFTP hosts.** An unconnected `sftp://` host from discovery switches the pane to the SFTP connect form seeded from it (host keys need their own prompt).
8. **Tree.** `network:///` is a tree root; the tree already expands any URI through `read_dir`, so `network:/// ▸ smb://nas/ ▸ share ▸ folders` works with no tree change beyond treating `smb://host/` as a root-like node.
