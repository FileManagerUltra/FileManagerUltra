## Detection
- `fm-engine::devices` holds a `DeviceList` (`Vec<Device {name, mount: VfsUri, total, free, fs, id, kind, removal}>`). Discovery includes removable hardware and user-mounted volumes (data disks, network mounts and virtual volumes such as VeraCrypt), excluding the system volume, pseudo filesystems and implementation-only mounts. Deduplicate by mount identity; do not require `is_removable()` for inclusion. Unknown capacity is shown as unavailable, not zero.
- Linux discovery reads bounded `/proc/self/mountinfo` metadata plus `sysinfo::Disks` capacity and `/dev/disk/by-label` labels. This also exposes network and virtual mounts omitted by sysinfo. macOS uses sysinfo plus `diskutil info -plist`; Windows uses fixed PowerShell/CIM queries for non-system drive letters, including network mappings. Platform adapters compile in Linux fixture tests too. Real mounted VeraCrypt checks on macOS/Windows remain a manual gate. A label alone is not proof of VeraCrypt ownership.
- The scan runs on a dedicated single-flight worker every 2 s while the app has focus (every 10 s unfocused), refreshing on focus regain. This intentionally isolates potentially hung mount queries from local file-operation jobs. It never runs on the UI thread. A scan that exceeds 1 s, or returns an error, keeps the previous list. A timed-out worker is not replaced until it exits, preventing abandoned-thread accumulation.
- The list is diffed; only a changed list bumps a generation counter the UI redraws on. Plug and unplug notices are shown in the status line ("USB_STICK connected").

## Commands
- `devices.refresh` rescans now. `devices.eject {uri}` ejects removable hardware; `devices.dismount {uri}` detaches a supported mounted volume without powering off its host disk.
- Removal runs on the `local` lane using fixed tools. Linux uses `udisksctl unmount` then `power-off` only for a verified external disk with no other mounted filesystem on it; otherwise it offers volume-only Dismount. Network mounts use non-forced `umount`. macOS offers volume-scoped `diskutil unmount` for identified physical volumes rather than ejecting a whole disk containing other volumes. Windows offers Shell.Application Eject only for removable drives with a volume serial number, using a fixed PowerShell script and a separately validated drive-letter environment variable. The mount identity is revalidated from OS metadata before execution and disappearance is checked afterward.
- Panes showing the device are navigated to Home before the eject starts; a busy device reports the tool's error text as an actionable notice.
- Removal capability is explicit, not inferred from the removable flag alone. VeraCrypt-owned mounts require a verified VeraCrypt-specific dismount adapter using the installed CLI and the exact listed volume identity. Do not send them to hardware power-off or assume generic unmount closes their encrypted mapping. If ownership or a safe adapter cannot be established, keep browsing available, disable Dismount and explain how to use VeraCrypt. Never request, store or log a password.
- Dismount is non-forced, checks active application transfers first, surfaces errors, and rescans after completion. Success is shown only when the operation is confirmed; unsupported or failed operations never masquerade as success.
- A disappeared mount invalidates cached/in-flight listings and blocks new application operations below its old mount point until it reappears. This avoids copying into the underlying directory after unplugging. In-flight filesystem calls cannot be cancelled by this guard; their normal OS errors are still surfaced.

## UI
- Places gains a Devices block above Places, rendered only when the list is non-empty. Row: volume icon, label and removal action only; click opens (`nav.open`). Path/free/total remain in hover and move into the directory Preview, alongside filesystem and used space. Directory previews use the closest containing cached volume; thumbnail mode keeps its details expandable. Information summaries reuse the dialog guide's proportional typography, neutral headings and aligned wrapping values without changing document fonts. Removal actions are labelled Eject or Dismount according to capability, available through the row and its context menu, with an explanation when unsupported. Rows are drop targets like other Places. Go > Devices mirrors it. Collapse state persists with the pane layout like the other sections.
- Colours from tokens, both themes, snapshot tests.

## Risks
- Removable detection and mount ownership differ by OS. User-mounted volume discovery must not depend solely on `sysinfo`'s removable flag; test fixtures cover virtual and external disks reported as non-removable.
- A hung mount can stall a stat call; scans only read the mount table and `statvfs`-style numbers from `sysinfo` and run on the worker with a timeout.
